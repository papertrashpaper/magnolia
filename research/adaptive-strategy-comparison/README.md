## 戦術の採用率と、採用後の最終成績

自然な山札で全員が手札に合わせて戦術を選びます。毎回の配置で選び直します。主表では最初の配置の選択を対戦終了まで追います。終盤の勝ちが見えた場面で選ばれた戦術を「勝ちやすい」と誤認しにくくするためです。勝利シェアは単独1位=1、同率1位なら人数で分配します。

「実採用」は同率候補から決めた1方針。「分配」は同率候補へ1/候補数ずつ配った割合で、同じ価値の提案を名前だけで区別する影響を確認できます。選択率は、この選択アルゴリズムの採用率です。人間が狙える確率をそのまま示すものではありません。

## カードを初手に持ったとき、残すか交換するか

カードを初手に持つ条件を用意し、同じ乱数種・同じ初期手札・同じ席から、最初のマリガンだけ「そのカードを残す／交換する」を強制します。以降はどちらも同じ手札適応CPUです。相手は均衡評価型の固定方針。1枚のカードを山札または相手の手札と入れ替えて初手に用意し、全体の枚数を保存します。自然に初手へ来る確率はこの実験では測りません。カードごとに同じ乱数種集合を使っています。

差は残す側－交換する側。単なる「置いた人が勝った率」より、最初に残す判断の価値を比べやすい設計です。以降の手札や相手の配札は行動により分岐します。対象が2枚以上あるカードでは、初手の同名カードをすべて残す／すべて交換します。残したカードを後のラウンドに交換することは可能です。

## レアな君主ルート：理想手札での対照実験

初手を「人間の大商人、人間の行商、人間の君主、嵐のデーモン、ゴーレムの王」の5枚に揃え、1ラウンド目に収入2枚、2ラウンド目に人間の君主、3ラウンド目に嵐、4ラウンド目にゴーレムの王を前列の同じ横列へ置きます。以降も対戦が続く場合は手札適応CPUへ切り替えます。君主ボーナス9VPが嵐で18VPになります。最初の5枚は既存カードと交換し、枚数を保存。比較側も同じ理想手札から手札適応CPUで判断します。相手は均衡評価型です。

## 柔軟に選ぶこと自体の比較

同じ初期条件で、自分だけ手札適応型／前回上位の貯金固定型に入れ替えます。相手は均衡評価型。全員が手札適応型の主表とは別の条件です。前回のデータと直接勝率を引き算しません。手札適応型は複数の戦術と仮想ゲームを調べるため、固定型より計算量が多く、差には探索量の違いも含まれます。

## 選択モデルと限界

- 前回の8方針から配置・交換を提案。前回の「適応型」は重みが均等な固定方針で、本比較の手札適応CPUとは違います。表では均衡評価型と呼びます。
- 各方針の重み付き評価値同士は比較しません。それぞれを同じルールで試した仮想ゲームの成績を共通基準で比較します。
- 配置では2通りの仮想手札・山札で今と次のラウンドを処理。交換では1通りで今のラウンドを処理。探索幅は2。仮想の相手は均衡評価型。終局した仮想ゲームは勝利シェアとVP差、終局前は共通の均衡評価から判断します。全対戦を先読みした最適選択ではありません。
- ゲームと仮想世界の乱数種は、SHA-256で混ぜてからLCGを初期化します。連番の乱数種を直接初期状態に入れた予備出力は採用していません。10,000山札の初期手札分布を [配札検査](deal-audit.json) に保存しました。
- 仮想の未公開カードは全カード枚数から自分の手札、全員の公開盤面、公開捨て札を引いた候補から生成します。実際の相手の手札・山札・ゲームの乱数種は入力しません。仮想世界の乱数は公開状態と自分の手札から作ります。
- 同率候補の選択は公開状態に基づく再現可能な振り分けです。同率候補が多い場合、方針名別の成績を強く解釈できません。採用した方針は次の手札で変わり得るので、初回の方針だけで勝ち切った成績ではありません。
- 実際の対戦では全員の決定を同じ状態から先に計算してから提出。同時決定の順番で他人の配置を先に知ることはありません。
- 採用率と条件付き成績の95%区間は、対戦単位をまとめて2,000回再標本化。カード保持と固定型比較は配札条件ごとの差を2,000回再標本化。多重比較補正なし。少数の全勝では再標本化の区間も過度に狭くなるため、全勝を勝利保証と解釈しません。
- 完成形の条件は結果を見る前にコードで定義。完成形同士は重複可能。「揃え2件」は成立した種族・職業ボーナスの件数を指し、同じ配置で両方が成立した場合も2件と数えます。技術VP係数はVPフェーズで技術レベルに掛ける係数の合計、追加収入は基本3金を除いたカードの効果です。
- 現在の仮の枚数構成（102枚）での比較です。正式な枚数が変われば出現率や順位も変わります。全対戦でカード102枚を保存。欠落・重複、勝利シェアの合計、VP発生源の合計を検証します。

## 再利用

Node.js 22以上。リポジトリ直下で実行：

```sh
npm run audit:research-deals
npm run analyze:adaptive
npm run replay:adaptive -- 0
npm run benchmark:adaptive
npm run validate:adaptive-retention
npm run benchmark:royal-route
npm run replay:adaptive -- 0 --royal
npm run replay:adaptive -- 0 --validation
```

ADAPTIVE_SEEDSで自然な山札・固定型比較の配札条件数、ADAPTIVE_CARD_SEEDSでカード保持比較の条件数、ADAPTIVE_WORKERSで並列数を変更できます。途中のresults.jsonlがあれば未完了IDから再開。コードや条件を変える場合はresults-config.json、results.jsonl、results.jsonl.gzを別フォルダへ保管してから実行します。分析は圧縮データにも対応。保存データは小さな分割ファイルで、archives.jsonの順に結合しSHA-256を確認して読み込みます。FINDINGS.mdはこの実行に対する考察なので、再実行後に見直してください。
