# 長期計画CPUの比較

2026-10-08。高額カードを収入の成長と組み合わせる長い完成筋を、研究用CPUで検証する。

## 実装

`scripts/planning-strategies.mjs` は、現在の手札から最大4ラウンドの合法な配置計画を作り、必要なカードを交換せずに残す案を比較する。完成形の得点だけでなく、資金、配置順、前線、相手によるゲーム終了を評価する。君主ルートのカード名・手順は登録していない。将来引くカードは仮想世界で抽選し、相手の実際の非公開手札は参照しない。

既存CPU・新CPUは同じ初期配札と席で対戦する。行動により補充枚数が変わるため、その後の全ドローが一致する実験ではない。[比較条件と反映条件](METHOD.md) は本比較の集計前に固定した。

## 結論と反映判断

**研究用CPUには通常配札で改善が見られたが、ゲーム内CPUへの反映は見送る。** 通常配札の256組では勝利シェアが43.36%→52.93%、同じ配札での差は+9.57ポイント（95%区間 +3.32～+15.82）。ただし凄腕相手の64組では32.81%→25.00%、差は−7.81ポイント（−20.31～+6.25）で、事前に定めた「平均差が正」の条件を満たさない。凄腕相手での悪化も確定ではないが、改善確認前に移植する根拠はない。

これは新旧CPUを互いに直接対戦させた勝率ではなく、同じ初期配札で同じ種類の相手と戦わせ、自分だけを入れ替えた比較である。

## 長い君主ルートの見落とし

理想手札を渡した64組で、君主3枚の職業ボーナス完成は旧CPU 0/64、新CPU 10/64。新CPUのうち8対戦では嵐も盤面にあった。計画が勝率・完成率の改善につながる例はできたが、完成したのは15.63%にとどまる。「理想手札を渡せば毎回完成筋を選べる」とは言えず、既存の手順固定CPUが出した高勝率とも別の実験である。

通常配札では双方とも君主ボーナス完成0件。このサンプルから自然配札での君主ルートの可能性を評価し切ることはできない。今回のCPU成績だけを根拠に41枚の★評価を確定・書き換えることも行わない。

## 検証と残る課題

896対戦すべてが合法に完走し、41種類・102枚の内訳を保存した。448組すべてで初期配札の一致を確認。本比較と追加検証でそれぞれ旧CPU・新CPU・理想君主手札の新CPUの3対戦を再実行し、時間以外の全記録が一致した。テスト82件もすべて通過した。

単独実行の5人戦2配札でも、新CPUの平均判断時間は1.52秒・1.46秒、最大2.20秒・1.95秒だった。旧研究CPUは平均0.41秒・0.33秒。事前に定めた1秒の応答条件も満たさない。これは同じ環境のNode.js計測で、ブラウザでの時間ではなく、全局面を代表する測定でもない。詳細は [timing.json](timing.json) に保存する。

凄腕相手の差と応答時間を改善するまではゲーム内に反映しない。原因候補として、仮想世界の相手は均衡評価型なので、凄腕の配置選択を十分に予測できていないことがある。また、毎回の再計画で完成筋が途中で外れる例を履歴から調べる余地がある。いずれも原因を確定した説明ではなく、次に切り分ける仮説である。次の調整後は今回の896対戦で繰り返し最適化するだけで済ませず、別の配札で検証する。

## 再現

```sh
npm run benchmark:planning
npm run validate:planning
node scripts/analyze-planning.mjs results --replay
node scripts/analyze-planning.mjs validation --replay
npm run analyze:planning
node scripts/time-planning.mjs
```

本比較と独立追加検証は各448対戦。設定JSONに乱数種の範囲、探索幅、CPUとルールのソースSHA-256を保存する。圧縮対戦記録は `archives.json` で分割ファイルと検証用SHA-256を記録し、分析スクリプトが結合・照合する。計測時間以外の対戦内容は再現照合する。

人数別の初期配札は同じ乱数種を共有するため、全体の95%区間は乱数種単位で再標本化する。引き分けは勝利シェアを分配する。理想君主手札を設定した実験は、通常の配札の結果と混ぜない。

## 解釈上の範囲

相手は均衡評価型とゲーム内「凄腕」に限る。この結果だけで人間相手や全難易度の強さを確定しない。計画生成は探索幅の限られた近似であり、4ラウンドを超える筋や、途中で新しく引いたカードを必要とする筋を網羅していない。計画候補なしの4ラウンド対照も用意するが、新CPUと計算量まで等しい対照ではない。

予備実行は設計・保存処理の確認用で、最終結果へ含めない。本比較・追加検証の結果を見てパラメータを変更することも行わない。
