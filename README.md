# マグノリア ブラウザ版

人間とCPUを合わせて2～5人で遊ぶマグノリアの実装です。CPU対戦はブラウザのみで動き、オンライン対戦は付属のNode.jsサーバーで同期します。

## ローカルで遊ぶ

Node.js 22以上をインストールした環境で、このフォルダを開いて実行します。追加のnpm依存ライブラリはありません。

```sh
npm ci
npm start
```

ブラウザで http://localhost:3000 を開き、「CPU対戦を開始」を押してください。2～5人を選べます。対戦途中の状態はブラウザに保存され、「前回のCPU対戦を再開」で続けられます。

## GitHub PagesでCPU対戦を公開する

1. リポジトリの **Settings → Pages → Build and deployment → Source** を **GitHub Actions** に変更します。
2. **Actions → Test and publish game → Run workflow** を実行します。
3. 完了すると https://papertrashpaper.github.io/magnolia/ でCPU対戦を遊べます。以降はmainへの更新時に自動でテスト・公開します。

`public/`の内容だけが公開されます。オンライン対戦には次のサーバー準備が必要です。

## 公開中のオンライン対戦

https://magnolia-82c3.onrender.com/ またはGitHub Pagesで「オンライン対戦」を選びます。接続先は設定済みです。部屋を作成して招待リンクを友達に共有し、参加後に部屋主が開始します。足りない席はCPUで埋まります。無料サーバーの休止後は起動に1分ほどかかるため、接続画面で待ってください。

## オンライン対戦用サーバーをRenderに置く

1. https://render.com/ でアカウントを作成し、GitHubリポジトリ `papertrashpaper/magnolia` を接続します。
2. **New → Blueprint** からリポジトリを選ぶと、`render.yaml`の設定を利用できます。Web Serviceを手動で作成する場合はRuntimeをNode、Build Commandを `npm ci`、Start Commandを `npm start` にします。
3. 作成されたHTTPSのURLを、ゲーム画面の「オンライン対戦 → 対戦サーバーURL」に入力します。
4. 部屋を作成し、「招待リンクをコピー」で友達に共有します。友達はプレイヤー名を入れて参加します。
5. 部屋主が開始すると、空席はCPUで補充されます。ゲーム開始後の新規参加はできません。

同じサーバー上でゲーム画面も配信されるため、RenderのURLを直接開いて遊ぶこともできます。

### サーバーの環境変数

| 変数 | 初期値 / 用途 |
| --- | --- |
| `PORT` | ローカルでは3000。Renderではサービスが指定します。 |
| `ALLOWED_ORIGINS` | `https://papertrashpaper.github.io`。他のサイトから接続する場合は、許可するオリジンをカンマ区切りで指定します。 |

サーバーはゲーム状態の正本を管理し、各参加者には自分の手札と公開情報だけを送ります。全員の確定までは他人のカード交換・配置を公開しません。配置を確定した本人には配置後の盤面・残り手札・各値を表示し、再接続時にも復元します。対戦終了後は部屋主の「同じ部屋で再対戦」で、部屋番号・参加者・CPU・配点を引き継いで新しい対戦を始められます。再接続は同じブラウザの「前回の部屋に再接続」で行います。

**初期版の制限：** 部屋の状態はサーバーのメモリ上にあり、サーバーが再起動すると消えます。Renderの無料Web Serviceは無通信時に休止する場合があります。切断した人の自動CPU交代、部屋主の交代、ゲーム途中の新規参加は未対応です。

## 処理の表示

全員が同時に行動を確定した後、プレイヤーごとに配置を公開し、戦争・発展・収入・VPを順番に表示します。標準は「次の処理」を押して進める手動確認です。「自動再生（ゆっくり）」は約3.2秒ごとに進み、途中で停止できます。各増減にはカード名、配置ボーナス、基本収入などの理由と変更前後の値を表示します。各フェーズの最後に全員の増減一覧を表示します。技術・信仰の変化には、対応するレベルの上昇・低下（またはレベル据え置き）も表示します。

マリガンの中央メッセージや履歴は表示しません。全員の王国の下には裏向き手札を常時表示し、交換時は捨てるカードが消え、その後に補充カードが入ります。枚数だけを公開し、相手のカード内容は公開しません。

各王国には戦力値と技術・信仰のバーを表示します。バーの目盛りは0・1・3・7・15点（レベルの境界）で、区間ごとの幅は同じです。戦争の開始時には前線・射手のカードがぶつかり、1位のカードが残る演出を表示します。同率1位は両方残ります。演出によって実際の王国のカードは失われません。動きを減らすOS設定にも対応します。

配置は手札から王国の「＋」へのドラッグ＆ドロップ（マウス・タッチ）、またはカード選択と「＋」のクリックで行えます。配置カード一覧の横に現在のお金を大きく表示し、仮配置・取り消しのたびに更新します。

自分の仮配置と取り消しでも中央に理由つきの増減が出ます。全員の王国は常時一覧表示され、現在順位はVP順です。オンラインでは各自のペースで処理を確認し、ほかの参加者が先に進めた場合も確認中の表示は保持されます。

## 採用ルール

- 初期5金・手札5枚、技術・信仰・VPは0。
- 嵐のデーモンの配置コストは9金。
- ドローは持ち越した手札から捨てるものを選んでから5枚に補充。1フェイズ1回、初回も可能。
- 配置は最大2枚。各カードについて支払い → 配置時効果 → 成立した全配置ボーナスを処理し、次のカードへ進む。
- 配置しない枠1つにつき1金を、全配置処理の後に受け取る。このお金は同フェイズの配置コストに使えない。
- 初手を座標(0,0)に置き、上下左右へ広げる。座標は相対位置を表し、固定の3×3枠ではない。王国の幅・高さは各3マス以内。上側が前方。カードの移動・置き換えは不可。
- 同種族・同職業の縦横3枚で配置ボーナス。複数の列、種族と職業の同時成立はすべて処理。同じ列・種類のボーナスは1回のみ。
- 戦争の初期配点は2人で `[4,0]`、3～5人で `[5,3,0,0,0]`。各順位の配点を開始前に0～50VPで変更可能。
- 同戦力は同順位（順位＝自分より戦力が高い人数＋1）。後続の順位は飛ばす。
- 技術・信仰は15点上限。レベルは0点→0、1～2→1、3～6→2、7～14→3、15→4。
- 発展 → 基本3金とカード収入 → カードVPの順に自動処理。
- 誰かが40VP以上、または9体配置したラウンドの最後に終了。残金3金につき1VP、同点は同時優勝。
- カード効果は公式FAQに従う。同じ効果が複数ある場合は今回の独自設定として重複適用。嵐のデーモン2体ならボーナス4倍、人間の君主2体なら金によるVP9倍。

## 宿屋のチュートリアル

開始画面の「チュートリアルで遊ぶ」で、CPU「宿屋の常連」と1ラウンド練習できます。実際の山札から安いカードを交換して手札を用意し、手札交換・仮配置と取り消し・処理の確認を案内します。練習後も通常のCPU対戦として継続できます。

## CPUの強さと個別設定

共通設定に加え、「CPUごとに強さを設定」で人数分の難易度を組み合わせられます。オンラインではCPU用に確保した席の順で設定し、それ以外の空席には共通設定を使います。再対戦でも各CPUの設定を維持します。

- 弱い：合法な配置をランダムに選びます。
- 普通：直近の資源・戦力・ボーナスを見て、ややばらつきのある配置を選びます。
- 強い：2枚の配置順と組み合わせを比較し、戦争の配点も考慮します。
- 凄腕：公開カード枚数から4通りの仮手札を作り、自分と相手の行動を次ラウンドまで予測します。
- 覇王：候補12通り・仮手札4通りで現在から3ラウンドを比較し、悪い引きへの耐性も評価します。

相手の手札・未確定の行動・山札の順番は参照しません。旧保存データのCPUは普通として動作します。強さの差は確率的で、上位CPUが常に勝つ保証はありません。

`npm run benchmark:cpu` で隣接する難易度を24通りの山札・交互の席順（普通対強いは80通り）で比較し、3人・5人・2種類の戦争配点でも混合対戦を実行します。結果は `test/cpu-benchmark-results.json` に保存します。再現用に `CPU_BENCH_SEEDS` で試行数を変更できます。

## 戦術比較と再現

[戦術比較の記録](research/strategy-comparison/README.md) に8方針・2～5人の7,980対戦、相性、戦争配点・探索条件を変えた比較を保存しています。[戦術メモ](research/strategy-comparison/TACTICS.md) は実際の戦い方に読み替えるための考察です。席の入れ替えは初期手札の割当を均すために使います。

`npm run analyze:strategies` で保存データを再集計し、`npm run replay:strategy -- 0` で対戦IDから再現できます。`npm run benchmark:strategies` は全比較を再実行します。条件とソースのハッシュ、全対戦の圧縮記録、JSON・CSV集計も同じフォルダに保存しています。これは同じ探索予算の固定方針CPUの比較であり、人間の最適戦術を断定するものではありません。

固定方針比較の配札条件については [補足](research/strategy-comparison/ERRATA.md) があります。

[手札から戦術を選ぶ追加比較](research/adaptive-strategy-comparison/README.md) では、戦術の採用率と最終成績、完成形の出現率、君主など9種類のカードを初手に残す／交換する対照実験を記録しています。[考察](research/adaptive-strategy-comparison/FINDINGS.md) に使いどころをまとめました。`npm run analyze:adaptive` で再集計、`npm run replay:adaptive -- 0` で対戦再現、`npm run benchmark:adaptive` で再実行できます。

[全41種類のカード判断ガイド](research/adaptive-strategy-comparison/CARD_GUIDE.md) では、残す条件・出すタイミング・複数ルートの比較を整理しています。条件別の勝率を確定した表ではなく、既存の対戦比較と、同じ盤面で配置を変えた11例のルール計算に基づく暫定ガイドです。`npm run guide:cards` で一覧を生成、`npm run examples:cards` で判断例を再計算できます。

[全41種類の★評価](research/adaptive-strategy-comparison/CARD_RATINGS.md) に、4人戦中心の使いやすさ・得点力・資金繰りの暫定評価を保存しています。条件が整った局面の強さと普段の採用しやすさを区別し、再利用用JSONも付けています。

## 対戦保存と再接続

無料のRenderサービスには永続ディスクがないため、各参加者のブラウザにサーバーが作成した暗号化・認証付きバックアップを自動保存します。サーバー再起動後、同じサイト・同じブラウザから「前回の部屋に再接続」を選ぶと、その参加者が保存した最新状態から部屋を復元します。確定済みの操作・部屋番号・メンバー・手札・CPU設定・振り返りも保持します。接続が途切れた場合は自動で再接続を試みます。

バックアップはAES-256-GCMと圧縮を使い、ブラウザから相手の手札を復号したり、内容を改ざんしたりできません。復元は保存された参加トークンで認証します。保存番号で新旧を判定し、古いバックアップで部屋を上書きしません。復元後に別の参加者がより新しいバックアップを持って再接続した場合は、その状態へ更新します。バックアップの期限は最後の操作から7日です。

**制約：** サーバー再起動後、参加者全員がブラウザの保存データを消していたり、全員の保存が失敗していた場合は復元できません。参加者が切断していて受信しなかった操作は、その参加者のバックアップには含まれません。直前まで接続していた参加者から復元すると最新状態に戻れます。サーバーだけでの永続保存が必要な場合は、永続ディスクまたは外部データベースの導入が必要です。

### サーバー設定

- `ROOM_BACKUP_KEY`：32バイトの秘密鍵を64文字の16進数で指定。再起動・デプロイ間で同じ値を保持します。Gitには保存しません。鍵を変えると以前のバックアップは復元できなくなります。
- `ROOM_STORE_FILE`（任意）：サーバー側の暗号化保存ファイル。指定した場合、操作ごとに一時ファイル経由で保存し、起動時に読み込みます。Renderでは永続ディスク上のパスを使う必要があります。無料プランの一時ファイルはデプロイをまたいで保存できません。

鍵の生成例：`node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"`

接続状況は配信接続から判定し、複数タブを開いている場合は一方が接続していれば接続中と表示します。「考え中」「確定済み」「切断中・再接続待ち」を区別します。

## ラウンドの振り返り

完了した各ラウンドについて、プレイヤーごとの開始・終了時の資源、技術・信仰レベル、配置・戦争・発展・収入・VPの処理と増減理由を折りたたみ表示します。過去のラウンドも選べます。マリガンのカード内容・相手の手札・未確定操作は表示しません。

[長期計画CPUの比較](research/planning-cpu/README.md) では、最大4ラウンドの手札内計画とカード保持を研究用CPUへ追加し、既存CPUと同じ初期配札で比較します。通常配札・凄腕相手・理想君主手札・計画候補なしの対照を分け、896対戦では通常配札で改善が見られたものの、凄腕相手と応答時間の条件を満たさず、ゲーム内への反映は見送りました。`npm run benchmark:planning`、`npm run validate:planning` で再実行、`npm run analyze:planning` で再集計できます。

## 追加目標

開始画面で使用を選択できます（標準ではオフ、チュートリアルでは不使用）。提供された12枚からランダムに4枚を公開。カードに指定されたフェイズの終了時に判定し、最初に達成した全員に3VPを付与します。同じ判定時の同時達成も全員が得点。達成済み目標は再配布・再加点しません。所持金2金は配置終了時、12金は各フェイズ終了時の完全一致、収入7金は基本収入を含む当該フェイズの増加額です。

対戦画面には自分の進捗、配置予定を反映した進捗、公開盤面で条件を満たす／近づいている相手、全員の詳細を表示します。相手の手札は使用しません。CPUも未達成目標を配置評価に含めます。研究用比較は実行していません。
